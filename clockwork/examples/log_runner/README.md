# Log runner

The intent of log runner is to allow for playing existing Clockwork log files through a Clockwork system and having specified channels be recorded into a new log.
It also can be used to run a system in a deterministic fashion without a log input or a log output.
This example demonstrates how to connect a log publisher and writer, use generated configuration files, and execute the system.

## Connecting a log publisher

In order to publish a log on a channel, a `LogReaderPolicy` must be added for it.
The policy specifies a "source_name" which must correspond to a channel name contained in the log file.

```clockwork
// The channel to publish on
channel Chan1
{
    message_type: Tachyon<TestMessage>;
    max_num_messages: 11;
}

// Our log reader policy
policy LogReaderPolicy for Chan1
{
    source_name = 'test_channel';
}
```

The channel can then be connected to an appropriate Cog input.

```clockwork
box LogRunnerExampleBox
{
    new example_cog_subscriber: ExampleCogSubscriber;
    connect Chan1 to example_cog_subscriber.test_message_input;
}
```

We can also specify that a channel should be only used as a passthrough, and should publish from a log, and write directly to a new log.
In this case, the channel does not even need to go in a box.

```clockwork
// Another channel
channel Chan3
{
    message_type: Tachyon<TestMessage>;
    max_num_messages: 11;
}

// Our log reader policy
policy LogReaderPolicy for Chan3
{
    source_name = 'test_channel2';
}

// Our log writer policy (see next section)
policy ChannelLoggingPolicy for Chan3
{
    log_type = LogType::telemetry;
}
```

## Connecting to a log writer

Similar to the log publisher, a log writer is configured to log the output of a specific channel via a policy.
But the log writer uses the `ChannelLoggingPolicy`.
For the `ChannelLoggingPolicy` all that needs to be specified is that of `log_type = LogType::telemetry`.
Similar to the log reader, the channel can then be connected to an appropriate Cog input.

```clockwork
policy ChannelLoggingPolicy for Chan2
{
    log_type = LogType::telemetry;
}

box LogRunnerExampleBox
{
    new example_cog_publisher: ExampleCogPublisher;
    connect example_cog_publisher.test_message_output to Chan2;
}
```

## Using the generated config files

For running a log runner system we will need three configuration files that get generated by the clockwork compiler.
The names of these config files are quite long so it is recommended that you use `clk-deps` to actually generate the file names for you in the `outs` portion of the `clk` target definition.

In our example system case, our system clk target is called `log_runner_example_system_clk` so our process description file is going to end in `log_runner_example_system.proc.tachyon`.
The other two files relevant to Log runner:

- The log writer configuration, ending in `telemetry_logger_config.tachyon`
- The log publisher/reader configuration, ending in `log_reader_config.tachyon`

For our log runner example system, `clk-deps` will generate a `cc_binary` for us called `log_runner_example_exe`.
However, it will be generated with the appropriate config files for the `data` parameter, so these three config files will need to be added there manually.

```python
cc_binary(
    name = "log_runner_example_exe",
    srcs = [
        "log_runner_example_exe.cc",
        "log_runner_example_exe.hh",
        "log_runner_example_exe.inl",
    ],
    data = [
        ":log_runner_example_system.log_runner_example_system.SimCpu_log_reader_config.tachyon",
        ":log_runner_example_system.log_runner_example_system.SimCpu_telemetry_logger_config.tachyon",
        ":platforms.clockwork.examples.log_runner.log_runner_example_system.log_runner_example_system.proc.tachyon",
    ],
    deps = [
        ":example_cogs",
        "@clockwork//jewels/memory:memory_resource",
        "@clockwork//jewels/memory:pmr_shared_ptr",
        "@clockwork//clockwork/scaffolding:abstract_casing",
        "@clockwork//clockwork/scaffolding:casing",
        "@clockwork//clockwork/scaffolding:main",
    ],
)
```

## Running the system

Below are the command line inputs to be used when running with log runner.
These are in addition to the path to the process description file, which gets passed without any arguments.
Note that when running with log runner, the deterministic-runner flag must be passed.
If either a sim-start-time or sim-end-time is omitted, than an input log file must be specified.
Otherwise, the times in the log will be used to dictate the missing value.

- deterministic-runner - switch that specifies the deterministic runner should be used.
  This is required to be set if running with Log Runner.
- input-log-uri - URI of the input log file.
  This is the log file which messages will be published from.
- output-log-uri - URI of the output log file.
  This is the log file which configured channels will be written to.
- log-publisher-config - file path to the log publisher configuration Tachyon file.
- log-writer-config - file path to the log writer configuration Tachyon file.
- sim-start-time-ns - start time of the simulation in nanoseconds.
- sim-end-time-ns - end time of the simulation in nanoseconds.

> [!TIP]
> This can be a lot of typing, so it is recommended that you use the `command` Bazel rule as a short cut.

```python
load("@rules_multirun//:defs.bzl", "command")

# Convenience target to avoid passing around the long path to config file every time
command(
    name = "run_example_system",
    arguments = [
        "--deterministic-runner",
        "--input-log-uri",
        "/tmp/test_log/log_runner/publisher/",
        "--log-publisher-config",
        "platforms/clockwork/examples/log_runner/log_runner_example_system.log_runner_example_system.SimCpu_log_reader_config.tachyon",
        "--output-log-uri",
        "/tmp/test_log/log_runner/log_writer/",
        "--log-writer-config",
        "platforms/clockwork/examples/log_runner/log_runner_example_system.log_runner_example_system.SimCpu_telemetry_logger_config.tachyon",
        "platforms/clockwork/examples/log_runner/platforms.clockwork.examples.log_runner.log_runner_example_system.log_runner_example_system.proc.tachyon",
    ],
    command = "@clockwork//clockwork/examples/log_runner:log_runner_example_exe",
)
```

Now you can just call `bazel run //platforms/clockwork/example/log_runner:run_example_system` and the command line options specified in the BUILD file will get passed for you.

### Generating the input logs

The example system has a log_gen application used to generate the input logs.
You can run it via `rm -r /tmp/test_log/log_runner/publisher; bazel run //platforms/clockwork/examples/log_runner:log_gen`
The `rm` is to clean up any logs that may have been there.

### Running the example system

To run the example system, you can run:
`rm -r /dev/shm/clockwork/pinion/pub/ ; rm -r /tmp/test_log/log_runner/log_writer/ ; bazel run //platforms/clockwork/examples/log_runner:run_example_system`
